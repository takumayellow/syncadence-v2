1 曲を遊び終えた後に、ランク・スコア・判定ごとの回数・最大コンボと、押したタイミングの偏りを出し、偏りが大きければ「入力の補正」の変更を 1 ボタンで提案する結果画面の部品です。

## このファイルが担うもの

- スコアとランクを大きく出し、自己ベストを更新したら札を付ける（L45-49）。
- PERFECT・GREAT・GOOD・MISS の回数と、最大コンボ / コンボの数の上限を並べる（L50-63）。
- 押したタイミングの中央値と、早すぎ・遅すぎの回数を出す（L64-69）。
- 中央値が 12 ms 以上ずれていれば、入力の補正をその分だけ動かすボタンを出す（L70-79）。
- R でもう一度、Esc か Q で選曲に戻る（L29-36、L82-87）。

この部品は自分では何も覚えていません（`useState` がありません）。結果の数はすべて props で受け取り、その場で計算して描くだけです。

## 呼ぶ・呼ばれる

| 向き | 相手 | 何のために |
|---|---|---|
| 呼ばれる | `src/ui/App.tsx` の L88-101 | 結果画面として描かれる |

`signedMs(ms)` は、ミリ秒を四捨五入し、正なら `+` を付けて ` ms` を足す関数です。15.4 は `+15 ms`、−8 は `-8 ms`、0 は `0 ms` になります。

## 読みどころ

- L26 の「自己ベストを更新したか」。前の記録が無ければ、何点でも更新です。
- L27 の提案の条件と、L74 の「足してから ±300 に収める」。結果画面は**今の補正に足す**のに対して、タイミング調整の画面（`src/ui/Calibrate.tsx` の L115）は**測った値で置き換えます**。なぜ違うのかを L64-81 で説明します。

## 落とし穴

- **ボタンの文字と、実際に入る値が違うことがあります。** L76 の矢印の右は `settings.inputOffsetMs + suggestion` をそのまま出しますが、L74 で入るのは ±300 に収めた値です。補正が `+295 ms` で提案が `+15` なら、ボタンには `+295 ms → +310 ms` と出て、押すと `+300 ms` になります。
- **ボタンは押した後も残り、もう一度押すと、もう一度足されます。** 提案は、プレイ中のずれ（L25）から決まり、そのずれは押しても変わりません。一方、矢印の左右は押した後の新しい補正で描き直されます。2 回押すと、ずれの 2 倍だけ補正が動きます。

@@ 24-28

L24 は props を引数の位置で取り出しています（文法の索引の『分割代入』）。

L25 の `timing` は、押したずれの一覧 `stats.deltas` をまとめたものです。`summarizeDeltas`（`src/game/stats.ts` の L15-23）は次の 3 つを返し、一覧が空なら `null` を返します。

| 項目 | 中身 |
|---|---|
| `median` | ずれの中央値（ミリ秒）。正なら遅め |
| `early` | 20 ms より早く押した回数 |
| `late` | 20 ms より遅く押した回数 |

ずれの一覧に入るのは、PERFECT・GREAT・GOOD と判定された押し方だけです（`src/game/session.ts` の L86）。ずれは、ノーツの時刻と押した時刻の差を実際の時間のミリ秒にしたもので、**今の入力の補正を引いた後の**値です（`src/game/engine.ts` の L124）。

L26 の `newBest` は、次の 2 つがどちらも真のときに真です。

1. `!autoplay` — オートプレイではない（オートプレイの結果は記録に残さないので）
2. `previousBest === null || stats.score > previousBest` — 前の記録が無いか、前の記録より高い。同点は更新に数えない

L27 の `suggestion` は、補正をどれだけ動かすかの提案です。条件演算子（文法の索引の『条件演算子 `? :`』）の `?` の左の条件を、左から順に確かめます。

1. `timing` — ずれの一覧が空でない
2. `timing.median !== 0` — 中央値が 0 ではない
3. `Math.abs(timing.median) >= SUGGEST_MS` — 中央値の大きさ（`Math.abs` は符号を取った値）が 12 ms 以上
4. `stats.deltas.length >= 20` — 20 回以上押している

すべて真なら `Math.round(timing.median)`（中央値を整数に丸めたもの）、どれかが偽なら `null` です。`&&` は左が偽ならそこで止まるので、1 で `timing` が `null` なら、2 以降で `timing.median` を読もうとして止まることはありません。2 は 3 が真なら必ず真なので、無くても結果は同じです。

20 回以上という条件は、数回しか押していない短いプレイで、たまたまのずれから補正を動かさないためです。12 ms と 20 回の値は `docs/design.md` の 5.4 節に書かれた決まりと同じです。

L70-79 は、L27 の提案があるときだけ出すボタンです。押すと L74 で次の順に計算して、設定を変えます。

1. `settings.inputOffsetMs + suggestion` — 今の入力の補正に、提案を足す
2. `Math.min(300, 1 の結果)` — 300 より大きければ 300 にする
3. `Math.max(-300, 2 の結果)` — −300 より小さければ −300 にする
4. `{ ...settings, inputOffsetMs: 3 の結果 }` — ほかの設定はそのままで、入力の補正だけを変えた新しい設定（文法の索引の『スプレッド構文 `...`』）
5. `onSettings(4 の結果)` — `App` に渡して保存してもらう

±300 は、設定を読み込むときの範囲（`src/storage.ts` の L40）と同じです。

**足す理由**: L25 のずれは、今の補正を引いた**後**の値です。補正 0 ms で中央値が +15 ms なら、15 ms 遅く押す癖があるので、補正を +15 ms にすれば、次からは判定に使う時刻が 15 ms 前へずれて、ぴったりになります。補正がすでに +10 ms で中央値が +15 ms なら、まだ 15 ms 残っているので、+25 ms にします。どちらも「今の補正 + 残ったずれ」です。

`src/ui/Calibrate.tsx` のタイミング調整は、補正を引く前の生のずれを測るので、測った値で**置き換え**ます。

例: 補正が 0 ms で、中央値が −12.5 ms なら、`Math.round(-12.5)` は −12 なので（JavaScript の `Math.round` は、ちょうど半分のときは大きいほうへ丸めます）、ボタンは「入力の補正を 0 ms → -12 ms にする」になります。
