いまどの画面（選曲・プレイ・結果・タイミング調整）を出しているかを 1 つの値で覚え、その値に応じて画面の部品を 1 つだけ選んで描く、ゲーム全体の「司令塔」の部品です。

## このファイルが担うもの

- 画面の切り替え。いまの画面を `screen` という 1 つの値（L34）で持ち、L75-120 の `switch` で、その値に合った部品を 1 つだけ返します。画面を移るときは `setScreen(…)` で値を入れ替えるだけです。
- 画面をまたいで使う値の持ち主。曲の一覧（`songs`）、設定（`settings`）、自己ベスト（`best`）、最後に選んだ曲と難易度（`selection`）はここで持ち、各画面には「値」と「値を変えたいときに呼ぶ関数」を渡します。
- 保存。設定・自己ベスト・選んだ曲は、変わるたびに `src/storage.ts` の関数でブラウザに保存します。起動時はそこから読み戻します（L31-33）。
- 起動時に曲の一覧（`public/songs/index.json`）を 1 回だけ読み込みます（L36-40）。

> **文法: 型注釈 `: 型`**
>
> TypeScript では、名前の後ろに `: 型` を書いて「ここにはこの種類の値しか入らない」と宣言できます。L24 の `songId: string` は「`songId` は文字列」という意味です。
>
> | 書き方 | 意味 |
> |---|---|
> | `string` | 文字列 |
> | `number` | 数（整数も小数も同じ型） |
> | `boolean` | `true` か `false` |
> | `null` | 「何も無い」ことを表す値 |
> | `Song`、`Difficulty` など大文字で始まる名前 | どこかで定義された型（ここでは `src/song/types.ts` で定義） |
>
> 型は TypeScript が**書いた時点で**検査するためのもので、JavaScript に変換すると消えます。実行中に型を確かめてくれるわけではありません（外から来た値を確かめる話は `src/storage.ts` で出てきます）。

> **文法: 型の別名 type と合併型 `|`**
>
> `type 名前 = 型;` は、型に名前を付ける書き方です。長い型を何度も書かずに済みます。
>
> `A | B` は「A か B のどちらか」という型で、**合併型**と呼びます。L25 の `number | null` は「数か、何も無いか」です。
>
> 型の側に `"select"` のような文字列をそのまま書くと、「その文字列そのものだけ」を許す型になります。`{ kind: "select" }` は「`kind` が `"select"` という文字列であるもの」だけです。
>
> L22-26 はこの 2 つを組み合わせ、「4 つの形のうちどれか 1 つ」を表しています。
>
> ```ts
> type Screen =
>   | { kind: "select" }                                   // 選曲: 追加の値なし
>   | { kind: "play"; songId: string; difficulty: …; … }   // プレイ: 曲と難易度
>   | …
> ```
>
> 先頭の `|` は飛ばして読んで構いません（並びをそろえるために置いてあります）。`{ }` の中の `;` は項目の区切りです。
>
> このように「共通の `kind` で、どの形かを見分けられる」合併型を使うと、`if (screen.kind === "play")` や `switch (screen.kind)` で場合を分けた先で、TypeScript がその形の項目（`songId` など）だけを使えるようにしてくれます（L75-120）。`kind` が `"select"` の値から `songId` を読もうとすると、書いた時点でエラーになります。

各項目の前の `readonly` は「作った後に書き換えない」印です（文法の索引の『interface と readonly』）。画面の値は書き換えず、移るときは新しい値を丸ごと作って `setScreen` に渡します。

4 つの画面で持つ値:

| `kind` | 持つ値 | 使う場所 |
|---|---|---|
| `"select"` | なし。選んだ曲は `selection`（L33）で別に持つ | L104-119 |
| `"play"` | 曲 ID、難易度、やり直しの回数 `attempt` | L76-87 |
| `"result"` | 曲データ全体、難易度、結果の数値 `stats`、**このプレイ前の**自己ベスト `best`（無ければ `null`）、オートプレイだったか | L88-101 |
| `"calibrate"` | なし | L102-103 |

`"play"` が曲データそのもの（`Song`）ではなく曲 ID（文字列）を持つのは、曲データの読み込みをプレイ画面の側（`src/ui/Play.tsx`）で行うからです。結果画面に入るときは、プレイ画面が読み込んだ `Song` をそのまま受け取って持ちます（L64, L68）。

> **文法: 関数コンポーネントと props**
>
> React では、画面の部品（コンポーネント）を**「受け取った値から、描くべき JSX を返す関数」**として書きます。名前は大文字で始めます（JSX で `<App />` と書いたときに、HTML のタグと区別するため）。
>
> ```tsx
> export function App() {
>   …
>   return <SongSelect songs={songs} … />;
> }
> ```
>
> 部品に渡す値を **props**（properties の略）と呼びます。L80 の `songId={screen.songId}` は、`Play` という部品に `songId` という名前で値を渡しています。受け取る側の `src/ui/Play.tsx` は L25 で
>
> ```tsx
> export function Play({ songId, difficulty, settings, onFinish, onRetry, onQuit }: Props) {
> ```
>
> と、渡された props を 1 つの入れ物として受け取り、中身を名前ごとに取り出しています（取り出し方は下の『分割代入』）。`App` は誰からも props を受け取らないので `()` が空です。
>
> props は**親から子への一方通行**です。子が親の値を変えたいときは、親が渡しておいた関数（`onFinish` や `onSelect` など、`on` で始まる名前にする習慣があります）を呼んで頼みます。
>
> React はこの関数を**何度も呼び直します**。覚えている値（下の `useState`）が変わるたびに関数をもう一度呼び、返ってきた JSX を前回と比べて、違う所だけページを書き換えます。これを「描き直し（再レンダー）」と呼びます。ですから関数の中の `const` は描き直しのたびに作り直されます。

> **文法: useState**
>
> 関数は呼ぶたびに最初から実行されるので、普通の変数では前回の値を覚えておけません。`useState` は「React に値を預けておき、描き直しのたびに最新の値を返してもらう」ための関数です（`use` で始まる React の関数を「フック」と呼びます）。
>
> ```tsx
> const [screen, setScreen] = useState<Screen>({ kind: "select" });
> ```
>
> - 引数 `{ kind: "select" }` は**最初の 1 回だけ**使う初期値です。
> - 返ってくるのは 2 つ組で、1 つ目 `screen` がいまの値、2 つ目 `setScreen` が値を変える関数です。
> - `setScreen(新しい値)` を呼ぶと、React が値を入れ替えて `App` を描き直します。`screen = …` と直接代入しても React は気づかず、画面は変わりません。
> - `setScreen((prev) => 新しい値)` と関数を渡すと、「直前の値 `prev` から新しい値を作る」という頼み方になります（L48, L60）。
> - 初期値の代わりに関数を渡すと（L31 の `useState<Settings>(loadSettings)`）、React は**最初の 1 回だけ**その関数を呼んで、戻り値を初期値にします。`useState(loadSettings())` と書くと、描き直しのたびに `loadSettings()` が呼ばれて（結果は捨てられて）しまいます。

> **文法: 分割代入**
>
> 配列やオブジェクトの中身を、1 文で複数の変数に取り出す書き方です。
>
> ```ts
> const [songs, setSongs] = useState(…);  // 配列の 0 番目を songs、1 番目を setSongs に
> const { ctx } = audioKit();             // オブジェクトの ctx という項目を ctx に
> ```
>
> 配列は `[ ]` で**位置**で取り出し、名前は自由に付けられます。オブジェクトは `{ }` で**項目の名前**で取り出し、同じ名前の変数になります（`src/ui/Calibrate.tsx` の L42）。
>
> 関数の引数の位置にも書けます。`function Result({ song, difficulty, … }: Props)`（`src/ui/Result.tsx` の L24）は、「1 つ目の引数として受け取ったオブジェクトから `song` や `difficulty` を取り出す」という意味です。React の部品の props の受け取りはほとんどこの形です。`{ song, large = false }`（`src/ui/SongSelect.tsx` の L27）のように `= 値` を添えると、その項目が無いときの既定値になります。

> **文法: ジェネリクス（型引数 `<T>`）**
>
> `useState<Settings>(…)` の `<Settings>` は、関数に渡す「型の引数」です。`useState` はどんな種類の値でも預かれるように作られていて、`< >` で「今回は `Settings` 型の値を預ける」と指定します。指定すると、返ってくる値も `Settings` 型、`setSettings` に渡せるのも `Settings` 型だけになります。
>
> 型の引数を受け取れる関数や型を**ジェネリクス**と呼びます。初期値から型が分かるときは省略できますが、L29 のように初期値が `null` だと「`null` しか入らない」と推し量られてしまうので、`<readonly SongSummary[] | null>`（「`SongSummary` の読み取り専用の配列か、`null`」）と明示しています。

`T[]` は「`T` の配列」という型で、前に `readonly` を付けると「要素を足したり書き換えたりしない配列」になります。

この部品が覚えている値は 6 つです。

| 値 | 初期値 | 意味 |
|---|---|---|
| `songs` | `null` | 曲の一覧。`null` の間は読み込み中 |
| `error` | `null` | 一覧を読み込めなかったときのメッセージ |
| `settings` | `loadSettings()` の戻り値 | ノーツの速さ・補正・音量などの設定（`src/storage.ts`） |
| `best` | `loadBest()` の戻り値 | 自己ベストの表。`"fur-elise:hard"` のような「曲 ID:難易度」をキーにしたスコア |

> **文法: アロー関数**
>
> `(引数) => 式` または `(引数) => { 文…}` は、名前の無い関数をその場で作る書き方です。
>
> ```ts
> (e: unknown) => setError(…)     // e を受け取り、setError(…) の結果を返す関数
> () => { loadIndex()…; }         // 引数なし。{ } の中の文を実行する関数
> ```
>
> - `=>` の右が `{ }` でなければ、その式の値がそのまま戻り値になります（`return` を書かない）。`{ }` で囲んだら、値を返すには `return` が要ります。
> - 引数が無ければ `()`、1 つなら `(x)`、複数なら `(a, b)` です。型注釈を付けるときは `(e: unknown)` のように書きます。
> - 変数に入れれば普通の関数と同じように呼べます（`const toSelect = … () => …;`、L73）。
> - `function f() { … }` との違いのうち、このコードで効くのは「その場で書ける短さ」だけです。React のコードでは、部品に渡す関数や、他の関数の引数として渡す関数の多くをアロー関数で書きます。

> **文法: useEffect**
>
> 部品を描いた**後に**、画面の外とのやり取り（ファイルの読み込み、キー入力の受け付け、保存など）をするための関数です。
>
> ```tsx
> useEffect(() => {
>   やりたい処理
>   return () => { 後片付け };   // 省略可
> }, [見張る値1, 見張る値2]);
> ```
>
> - 第 1 引数の関数は、描き終えた後に React が呼びます。
> - 第 2 引数の配列（依存配列）に書いた値が、前回の描画から**変わったときだけ**、もう一度呼びます。L40 のように空の配列 `[]` なら、部品が画面に出たときの **1 回だけ**です。配列ごと省略すると、描き直しのたびに毎回呼ばれます。
> - 第 1 引数の関数が関数を返すと、それは「後片付け」として、次に呼び直す前と、部品が画面から消えるときに呼ばれます。キー入力の受け付けを止めるのに使います（`src/ui/SongSelect.tsx` の L62）。
> - `StrictMode`（`src/main.tsx` の L9）の下では、開発中だけ「1 回目 → 後片付け → 2 回目」と余分に走ります。後片付けを正しく書いていれば、結果は 1 回のときと同じになります。
>
> 部品の関数の本体に直接書かないのは、本体は描き直しのたびに何度も呼ばれるからです。本体に `loadIndex()` を書くと、描き直すたびに読み込みが走ります。

`loadIndex()` は曲の一覧をネットワークから読み込む関数で（`src/song/load.ts` の L12）、すぐには結果を返さず「後で結果が届く約束」（Promise）を返します（文法の索引の『async / await と Promise』）。L38-39 はその約束に、届いたときの処理をつないでいます。

1. `.then(setSongs)` — 一覧が届いたら、それを `setSongs` に渡す。`setSongs` を呼ぶと `songs` が入り、`App` が描き直されて一覧が出る。`.then((list) => setSongs(list))` と同じことを、関数そのものを渡して短く書いている
2. `.catch((e: unknown) => …)` — 途中で失敗したら（ファイルが無い、形式が違うなど）、失敗の理由 `e` を受け取って `setError` に入れる

> **文法: instanceof**
>
> `値 instanceof Error` は、「その値が `Error` の仲間として作られた物か」を真偽で返します。`throw` で投げられるものは何でもよいので（文字列でも数でも）、`.catch` で受け取った `e` が本当にエラーかは分かりません。そのため TypeScript は `e` を `unknown`（「何か分からない値」。確かめるまで中身を使えない型）にしておき、`instanceof Error` で確かめてから `e.message`（エラーの説明文）を読みます。

> **文法: 条件演算子 `? :`**
>
> `条件 ? A : B` は、条件が真なら A、偽なら B になる**式**です。`if` 文と違い、値を返すので代入や引数の中に書けます。L39 は「`e` がエラーならその説明文、そうでなければ決まった文」を `setError` に渡しています。

失敗したときは `songs` が `null` のまま `error` に文が入ります。選曲画面（`src/ui/SongSelect.tsx` の L90-91）は `error` があればそれを出し、`songs` も `error` も無い間は「読み込み中…」を出します。

> **文法: オプショナルチェーン `?.` と `??`**
>
> - `a?.b` は「`a` が `null` か `undefined` なら、そこで止めて `undefined` を返す。そうでなければ `a.b`」です。`a.b` と書くと、`a` が `null` のときにエラーで止まります。
> - `a?.[0]` は配列の添字版、`a?.(…)` は関数呼び出し版です。
> - `a ?? b` は「`a` が `null` か `undefined` なら `b`、そうでなければ `a`」です。「値が無いときの代わり」を書くのに使います。`a || b` と似ていますが、`||` は `0` や空文字 `""` も「無い」とみなして `b` にしてしまうのに対し、`??` は `null` と `undefined` だけを置き換えます。
