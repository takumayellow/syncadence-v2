@@ 11-13

> **文法: ジェネリクスの制約 `extends` と `keyof`、`T[K]`**
>
> - `keyof Settings` は、`Settings` の項目名を全部並べた合併型です。`"approachSeconds" | "inputOffsetMs" | "visualOffsetMs" | "keysound" | "volume" | "rate" | "autoplay"` と同じです。
> - `Settings[K]` は、「`Settings` の項目 `K` の値の型」です。`Settings["volume"]` は `number`、`Settings["keysound"]` は `boolean` です。
> - `<K extends keyof Settings>` は、型引数 `K`（文法の索引の『ジェネリクス（型引数 `<T>`）』）に「`keyof Settings` のどれかでなければならない」という制約を付けます。
>
> 合わせると、`set` は呼ぶたびに次のように型が決まります。
>
> | 呼び方 | `K` | `value` の型 |
> |---|---|---|
> | `set("volume", 0.5)` | `"volume"` | `number` |
> | `set("keysound", true)` | `"keysound"` | `boolean` |
>
> `set("volume", true)` や `set("speed", 1)` は、型の検査で誤りになります。
>
> `.tsx` のファイルでは、アロー関数の前の `<K>` だけだと JSX のタグと見分けがつかないので、`<K extends …>` のように `extends` を書いて型引数だとはっきりさせる必要があります。

L12 の `set(key, value)` は、設定の 1 つの項目だけを変えた新しい設定を作って、`onSettings` に渡します。

1. `...settings` — 今の設定の項目を全部写す
2. `[key]: value` — 項目名 `key` の値を `value` にする。`key` が `"volume"` なら `volume: value` と書いたのと同じ
3. `onSettings(1 と 2 でできた設定)` — `App` に渡す

もとの `settings` は書き換えずに、新しいオブジェクトを作ります。React は「オブジェクトが新しくなったか」で変化を見つけるので、もとを書き換えると変化に気付けません。

@@ 14-28

> **文法: 制御された入力欄（value と onChange）**
>
> React では、入力欄に `value={値}` を渡すと、入力欄にはいつもその値が表示されます。利用者が動かしても、`value` が変わらなければ元に戻ります。値を変えるには、`onChange` で変化を受け取り、もとの値（ここでは設定）を変えて、描き直してもらいます。
>
> 1. 利用者がスライダーを動かす
> 2. `onChange` が呼ばれ、`e.target.value` で新しい値を受け取る
> 3. `set` で設定を変え、`App` が保存して描き直す
> 4. 新しい設定から `value` が計算され、スライダーがその位置になる
>
> 表示される値と設定がいつも一致するので、「画面ではこう見えるのに、設定は違う」ということが起きません。このように React が値を握っている入力欄を「制御された入力欄」と呼びます。チェックボックスでは `value` の代わりに `checked` を使います（L70、L74）。

> **文法: Number() で文字列を数に直す**
>
> `e.target.value` は、スライダーでも数の入力欄でも、いつも**文字列**（`"2.5"`）です。`Number("2.5")` で数の 2.5 にしてから使います。
>
> 数として読めない文字列は `NaN`（「数ではない」を表す特別な数）になり、空の文字列 `""` は 0 になります。

ノーツの速さのスライダーです。`approachSeconds` は、ノーツが奥に現れてから判定線に届くまでの秒数で、小さいほど速く流れます。スライダーは右へ動かすほど値が大きくなるので、そのまま結ぶと「右へ動かすと遅くなる」ことになります。そこで、表示と設定の間で向きを逆にしています。

| `approachSeconds`（設定） | スライダーの値 `4.6 - 設定` | 位置 |
|---|---|---|
| 4.0（一番遅い） | 0.6 | 左端 |
| 1.6（最初の値） | 3.0 | やや右 |
| 0.6（一番速い） | 4.0 | 右端 |

- L25 — スライダーの値から設定に戻す。内側から順に読むと:

  2. `4.6 - 3.1` — 設定の秒にする。1.5 に近い数（小数の誤差が付く）
  3. `* 10` して `Math.round` で整数にし、`/ 10` する — 小数第 1 位に丸めて、誤差を消す。1.5
  4. `set("approachSeconds", 1.5)`

入力の補正と表示の補正です。`type="number"` は数を打ち込む欄で、横の小さな矢印で 1 ずつ増減もできます。

| 補正 | 正にすると | 使う場面 |
|---|---|---|
| 入力の補正 | 判定に使う時刻から引くので、遅めに押しても合う | 押すのが遅れがち、キーボードの反応が遅い |
| 表示の補正 | 描く時刻から引くので、ノーツが遅れて判定線に届く | 画面の表示が音より遅れる |

`min`・`max` は、欄の矢印で動かせる範囲です。キーボードで打てば範囲の外の数も入るので、L53 と L65 でも範囲に収めます。L53 を内側から読むと:

1. `Number(e.target.value)` — 打った文字を数にする
2. `|| 0` — 数にできなければ 0 にする。欄を空にしたとき（`""` は 0）や、数として読めないとき（`NaN` は偽とみなされる）
3. `Math.round(…)` — 整数のミリ秒に丸める
4. `Math.min(300, …)` と `Math.max(-300, …)` — −300〜300 に収める
5. `set("inputOffsetMs", …)`

L65 は、項目が `visualOffsetMs` であるほかは L53 と同じです。
