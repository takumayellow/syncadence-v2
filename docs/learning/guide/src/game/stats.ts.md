押したタイミングのずれを数でまとめる関数です。結果画面の「早め・遅め」の表示と、タイミングを測る画面の「入力の補正」の値は、ここで計算します。

## このファイルが担うもの

- 数の並びの中央値 `median`（L1-6）。
- 1 プレイ分のずれの並びから、中央値と、早すぎ・遅すぎの回数を出す `summarizeDeltas`（L15-22）。
- メトロノームのクリックに合わせて叩いた時刻の並びから、ずれの中央値を出す `calibrate`（L29-39）。

ここでいう**ずれ**は、すべて「押した時刻 − 正しい時刻」の実時間ミリ秒です。**正なら遅め**、負なら早めです。

## 呼ぶ・呼ばれる

| 向き | 相手 | 何のために |
|---|---|---|
| 呼ばれる | `src/ui/Result.tsx` の L25 | `summarizeDeltas(stats.deltas)` で、結果画面の「中央値 +15 ms、早め 3 回、遅め 12 回」のような表示と、入力の補正の提案（L27, L74）を作る |
| 呼ばれる | `src/ui/Calibrate.tsx` の L56 | `calibrate(taps, clicks, 600)` で、入力の補正の値を測る |
| 呼ぶ | なし（`median` はこのファイルの中で使う） | |

ずれの並び `stats.deltas` は `GameSession` が判定のたびに貯めたもので、MISS 以外の押下だけを含みます（`src/game/session.ts` の L86）。押した時刻は、入力の補正を**入れた後**の位置で測っています（`src/game/engine.ts` の L121-125）。そのため結果画面は、中央値をいまの補正に**足した**値を新しい補正として提案します（`src/ui/Result.tsx` の L74）。

## このファイルで初めて出てくる文法

- L3 `[...values].sort((a, b) => a - b)` — 配列の並べ替えと、比べ方を決める関数
- L5 `sorted.length % 2 ? … : …` — 割った余りの `%` と、数をそのまま条件に使う書き方

## 読みどころ

- **平均ではなく中央値を使う。** たまたま大きく外した 1 回に引きずられないためです。
- **`calibrate` は、各タップを最も近いクリックと組にする。** どのクリックに合わせて叩いたつもりかは記録していないので、近さで決めます。

**中央値**は、数を小さい順に並べたときの真ん中の値です。個数が偶数なら、真ん中の 2 つの平均にします。

1. 空なら `null`（L2）。戻り値の型 `number | null` がその約束です
2. 写しを作って小さい順に並べる（L3）
3. 真ん中の番号 `mid` を出す（L4）。`Math.floor` は小数点以下を切り捨てる
4. 個数が奇数なら `sorted[mid]`、偶数なら `sorted[mid − 1]` と `sorted[mid]` の平均（L5）

> **文法: sort と比較関数**
>
> `配列.sort(関数)` は配列を並べ替えます。関数は 2 つの要素 `a` と `b` を受け取り、`a` を前にしたいなら負の数、`b` を前にしたいなら正の数、同じなら 0 を返します。`(a, b) => a - b` は、`a` が小さければ負になるので「小さい順」です。
>
> 関数を渡さないと、`sort` は要素を**文字列として**比べます。`[10, 9, 1].sort()` は `[1, 10, 9]` になります（文字の "1" が "9" より前なので）。数を並べるときは必ず比べ方を渡します。
>
> `sort` は**元の配列そのものを並べ替えます**。L3 の `[...values]` は、スプレッド構文（文法の索引の「スプレッド構文 `...`」）で写しを作ってから並べ替えるためのものです。`values` は `readonly`（書き換えない約束）で受け取っているので、そのまま `sort` することはできません。

> **文法: `%` と、数をそのまま条件に使う書き方**
>
> `a % b` は `a` を `b` で割った**余り**です。`7 % 2` は 1、`8 % 2` は 0 です。
>
> 条件の位置（`if (…)` や `条件 ? A : B` の左）に数を置くと、**0 は偽、それ以外は真**として扱われます。`sorted.length % 2 ? … : …` は、余りが 1（奇数）なら左、0（偶数）なら右、という意味です。

数で確かめると:

| 入力 | 並べた後 | `mid` | 結果 |
|---|---|---|---|
| `[3, 1, 2]` | `[1, 2, 3]` | 1 | `sorted[1]` = 2 |
| `[4, 1, 3, 2]` | `[1, 2, 3, 4]` | 2 | (`sorted[1]` + `sorted[2]`) / 2 = 2.5 |

`sorted[mid]!` の `!` は文法の索引の「非 null 表明 `!`」です。空の配列は L2 で返しているので、`mid` は必ず範囲内です。

`TimingSummary` は結果画面に出す 3 つの数の形です（文法の索引の「interface と readonly」）。

| 欄 | 中身 |
|---|---|
| `median` | ずれの中央値（ミリ秒）。正なら遅め |
| `early` | 20 ms より早く押した回数 |
| `late` | 20 ms より遅く押した回数 |

`summarizeDeltas(deltas)` は、

1. 中央値を出し、無ければ（一度も叩いていなければ）`null` を返す（L16-17）
2. `deltas.filter((d) => d < -20).length` — −20 ms より小さい（20 ms より早い）ものだけを残した配列の長さ、つまりその回数（文法の索引の「map・filter・reduce」）
3. 同じように、+20 ms より大きいものの回数

±20 ms 以内の押下は、早めにも遅めにも数えません。PERFECT の幅（±42 ms、`src/game/judge.ts` の L7）の中でも、さらに真ん中寄りを「ちょうど」とみなしています。

結果画面は、20 回以上叩いて中央値が ±12 ms 以上ずれていれば、入力の補正を中央値の分だけ動かすボタンを出します（`src/ui/Result.tsx` の L22, L27）。

**タップ較正**です。タイミングを測る画面（`src/ui/Calibrate.tsx`）で、600 ms ごとに鳴るクリック音に合わせて叩いた結果から、入力の補正の値を出します。

引数はどれもミリ秒で、物差しは「最初のクリックが聞こえた時刻を 0 とした時間」です。

- `taps` — 叩いた時刻の並び。`Calibrate.tsx` が、`SongClock` で「そのとき聞こえていた位置」に直して記録します（`src/ui/Calibrate.tsx` の L46, L66）。出力の遅れはここで差し引かれているので、残るのは押す癖と、ブラウザが申告しない遅れだけです
- `clicks` — 数えるクリックの時刻。`Calibrate.tsx` は 20 回鳴らし、最初の 4 回を耳慣らしとして除いた 2,400, 3,000, …, 11,400 の 16 個を渡します（同 L55）
- `intervalMs` — クリックの間隔（600）

**流れ**

1. タップを 1 つずつ見る（L31、文法の索引の「for…of」）
2. すべてのクリックの中から、そのタップに**いちばん近い**クリック `best` を探す（L32-35）
3. 近さが間隔の半分（300 ms）**未満**なら、ずれ `tap − best` を記録する（L36）。それ以上離れたタップは、どのクリックに合わせたのか分からないので捨てる
4. 記録したずれが 4 個以上なら、その中央値を返す。足りなければ `null`（L38）

**2 の探し方（L32-35）。** `best` は最初 `null` で、「まだ候補が無い」を表します。クリックを 1 つずつ見て、

- 候補がまだ無い（`best === null`）、または
- このクリックの方が、いまの候補よりタップに近い（`Math.abs` は絶対値。差の大きさだけを比べる）

なら、候補をこのクリックに替えます。`||` は「または」で、左が真なら右は見ません（文法の索引の「`&&` の短絡評価」と同じ考え方）。そのため、`best` が `null` のときに右側の `tap - best` を計算することはありません。

**数で追うと。** 3,000 ms のクリックに 40 ms 遅れて叩いた（`tap` = 3,040）なら、最も近いクリックは 3,000 で、ずれは +40 です。耳慣らしの最後のクリック（1,800）に合わせて叩いたタップは、最も近い数えるクリック 2,400 から 600 ms 離れているので捨てられます。

返した値は `Calibrate.tsx` で ±300 ms に収めて丸め、入力の補正 `inputOffsetMs` に**そのまま**入れます（`src/ui/Calibrate.tsx` の L115）。測るときは補正を使わないので、結果画面と違って足し算ではありません。+40 ms を入れると、判定に使う位置が 40 ms 分手前にずれ、聞こえてから 40 ms 後に押したときにちょうどになります（`src/game/engine.ts` の L121-125）。
