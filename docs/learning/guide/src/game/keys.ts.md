どのキーがどのレーンに当たるか、そして曲を始める合図にどのキーを使ってよいかを決める、小さな表と 3 つの関数です。

## このファイルが担うもの

- レーン数ごとのキーの割り当て `LANE_KEYS`（L2-5）。4 レーンは D・F・J・K、6 レーンは S・D・F・J・K・L。
- キーの名前をレーン番号に直す `laneOfKey`（L11-14）と、レーンの下に出す文字を作る `keyLabels`（L7-9）。
- READY の画面で「何かキーを押すとスタート」に使ってよいキーかを答える `isStartKey`（L19-22）。ブラウザや OS の操作に使うキーは除く。

## このファイルで初めて出てくる文法

- L17 `/^(F\d{1,2}|Tab|…)$/` — 正規表現
- L19 `Pick<KeyboardEvent, "code" | "ctrlKey" | "metaKey" | "altKey">` — 型から欄を選び出す `Pick`

## 読みどころ

- **キーは「場所」で決まる。** 使うのは `KeyboardEvent.code`（`"KeyD"` など）で、押したときに入る文字ではありません。英字配列でもほかの配列でも、キーボード上の同じ場所のキーが同じレーンになります。
- **開始の合図は「除く」方式。** 使ってよいキーを並べるのではなく、使ってはいけないキー（`RESERVED`）だけを並べ、それ以外は全部合図にします。

@@ 1-5

`LANE_KEYS` は、レーン数を鍵にして、左のレーンから順のキーの並びを引く表です（文法の索引の「Record 型」「interface と readonly」）。`Record<number, readonly string[]>` は「鍵は数、値は書き換えない文字列の配列」という型です。

| レーン数 | 難易度 | キー（左から） |
|---|---|---|
| 4 | EASY・NORMAL | D F J K |
| 6 | HARD・EXPERT | S D F J K L |

どちらも、キーボードのホームポジション（左手の人差し指が F、右手の人差し指が J）に指を置いたまま叩ける並びです。4 レーンは左右の人差し指と中指、6 レーンは薬指まで使います。

並べているのは `KeyboardEvent.code` の名前です。`code` は**キーの場所**の名前で、Shift を押していても、日本語入力が有効でも、同じキーなら同じ名前（`"KeyD"`）になります。押したときに入る文字（`KeyboardEvent.key`）を使うと、大文字・小文字や入力の方式で値が変わってしまいます。

@@ 6-10

レーンの下に出す文字の並びを作ります。

1. `LANE_KEYS[lanes] ?? []` — そのレーン数の並び。表に無いレーン数なら空の配列（文法の索引の「オプショナルチェーン `?.` と `??`」）
2. `.map((code) => code.replace("Key", ""))` — 各名前から `"Key"` を取り除く（文法の索引の「map・filter・reduce」）。`"KeyD"` は `"D"` になる

結果は 4 レーンなら `["D", "F", "J", "K"]` です。`PlayEngine` が作るときに 1 度だけ呼び（`src/game/engine.ts` の L52）、毎フレームの `Frame` に入れます。タッチだけの端末では `Play.tsx` が空にして渡すので出ません（`src/ui/Play.tsx` の L98）。

@@ 11-15

キーの名前 `code` が、いまのレーン数の並びの何番目かを返します。

`indexOf(code)` は、配列の中で `code` と同じ要素の番号（0 から）を返し、見つからなければ `-1` を返します。L13 で `-1` を `null` に直し（文法の索引の「条件演算子 `? :`」）、「レーンのキーではない」をはっきりさせています。戻り値の型 `number | null` がその約束です。

たとえば 4 レーンで `"KeyJ"` なら `2`（左から 3 番目のレーン）、`"KeyS"` なら `null` です。6 レーンでは `"KeyS"` は `0` になります。

@@ 16-22

**開始の合図に使わないキー**と、それを使った判定です。

> **文法: 正規表現**
>
> `/ … /` で囲んだものは**正規表現**で、「文字列がこういう形をしているか」を表す模様です。`模様.test(文字列)` は、文字列が模様に合えば `true` を返します。
>
> L17 で使っている記号:
>
> | 記号 | 意味 |
> |---|---|
> | `^` と `$` | 文字列の先頭と末尾。両方あると「文字列**全体**がこの形」 |
> | `( A \| B \| C )` | A か B か C のどれか |
> | `\d` | 数字 1 文字 |
> | `{1,2}` | 直前のものが 1 回か 2 回 |
> | `.*` | 何かの文字が 0 個以上（何が続いてもよい） |
>
> たとえば `F\d{1,2}` は「F の後に数字が 1〜2 個」で、`"F5"` や `"F12"` に合います。`Shift.*` は「Shift で始まる」で、`"ShiftLeft"` にも `"ShiftRight"` にも合います。`^` と `$` があるので、`"KeyF"` は `F\d{1,2}` には合いません。

`RESERVED` に入っているキー:

| 模様 | 合うキーの例 | 何に使われるか |
|---|---|---|
| `F\d{1,2}` | F5・F11・F12 | 更新・全画面・開発者ツール |
| `Tab` | Tab | 操作できる部品の間の移動 |
| `Escape` | Esc | 一時停止（プレイ中）、戻る（タイミングを測る画面） |
| `Meta.*`・`OS.*` | Windows キー・Command キー | OS の操作。`OS…` は古いブラウザでの同じキーの名前 |
| `Alt.*`・`Control.*`・`Shift.*` | Alt・Ctrl・Shift の単独押し | ほかのキーと組み合わせる修飾キー |
| `ContextMenu`・`PrintScreen` | メニューキー・PrtSc | 右クリックメニュー・画面の撮影 |
| `Browser…` | ブラウザの戻る・進む・更新のキー | ブラウザの操作 |
| `AudioVolume.*`・`MediaPlayPause` | 音量・再生のキー | 音量の調整など |

> **文法: Pick**
>
> `Pick<型, "欄1" | "欄2">` は、ある型から指定した欄だけを取り出した新しい型を作ります。`Pick<KeyboardEvent, "code" | "ctrlKey" | "metaKey" | "altKey">` は「`code`・`ctrlKey`・`metaKey`・`altKey` の 4 つを持つ物」です。
>
> 本物の `KeyboardEvent` はこの 4 つを持っているので、そのまま渡せます。一方、試験のときは `{ code: "KeyA", ctrlKey: false, metaKey: false, altKey: false }` のような小さなオブジェクトを渡すだけで済みます。関数が本当に使う欄だけを要求する書き方です。

`isStartKey` の判定（L19-22）:

1. Ctrl・Command（`metaKey`）・Alt を押しながらなら、合図にしない（L20）。Ctrl+R（更新）や Alt+Tab（ウィンドウの切り替え）で曲が始まらないようにするため
2. そうでなければ、`RESERVED` に**合わない**キーなら合図にする（L21）。`!` は「〜ではない」

Shift は L20 で確かめていないので、Shift+D は合図になります（Shift 単独は `RESERVED` で除かれる）。

**なぜ除く方式なのか。** 曲は「何かキーを押すとスタート」なので、どのキーを押した人にも応えたい一方、F11 で全画面にした・Alt+Tab で戻ってきた、という操作で勝手に始まると困ります。始めてよいキーを並べると漏れが出るので、始めてはいけないキーの方を並べています。

`Play.tsx` は合図に使ったキーを判定に回しません（`src/ui/Play.tsx` の L117-121）。D を押して始めても、その D はノーツを叩いたことになりません。
