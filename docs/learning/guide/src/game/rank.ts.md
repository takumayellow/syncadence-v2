`RANKS` の型 `readonly { readonly rank: string; readonly min: number }[]` は、外側から読むと「書き換えない配列で、その要素は `rank`（文字列）と `min`（数）の 2 つの欄を持つ物」です。`{ … }` の部分は、`interface` で名前を付けずに、物の形をその場で書いたものです（文法の索引の「kind で見分ける合併型」「interface と readonly」）。

> **文法: 数の中の `_`**
>
> `990_000` は `990000` と同じ数です。`_` は桁を読みやすくするための区切りで、値には何の影響もありません。3 桁ごとに入れるのが普通です。

| ランク | 最低のスコア | 満点に対する割合 |
|---|---|---|
| SSS | 990,000 | 99% |
| SS | 970,000 | 97% |
| S | 940,000 | 94% |
| A | 880,000 | 88% |
| B | 800,000 | 80% |
| C | 700,000 | 70% |
| D | 0 | 0% |

**数で感じをつかむと。** スコアは重みの平均 × 1,000,000 なので、たとえば判定の数（ロングノーツは始点と終点で 2 つ）が 400 の曲で SSS を取るには、失える重みが 400 × 0.01 = 4 までです。GREAT は 1 つで 0.25、MISS は 1 つで 1 を失うので、ほかが全部 PERFECT なら、GREAT 16 個か MISS 4 個までが SSS です。

**高い順に並べてあることが大事です。** 次の `rankOf` は先頭から順に見て、最初に条件を満たしたものを返すからです。

> **文法: 配列の find**
>
> `配列.find(関数)` は、要素を先頭から順に関数に渡し、関数が初めて真を返した**要素そのもの**を返します。最後まで真にならなければ `undefined` を返します。見つかった時点で残りは見ません。
>
> `filter`（文法の索引の「map・filter・reduce」）が「当てはまるもの全部の配列」を返すのに対し、`find` は「最初の 1 つ」だけを返します。

`rankOf(score)` の流れ:

1. `RANKS.find((r) => score >= r.min)` — 高い方から見て、`score` が最低のスコア以上になる最初のランクの行を探す
2. `?.rank` — 見つかればその行の `rank`（文字列）
3. `?? "D"` — 見つからなければ `"D"`

`?.` と `??` は文法の索引の「オプショナルチェーン `?.` と `??`」です。

たとえばスコア 955,000 なら、SSS（990,000）でも SS（970,000）でもなく、S（940,000）で初めて条件を満たすので `"S"` です。ちょうど 940,000 でも `>=` なので S になります。

D の最低は 0 なので、スコアが 0 以上なら必ずどれかが見つかります。`?? "D"` が効くのは負のスコアのときだけで、スコアの計算からは負にならないので、念のための備えです。
