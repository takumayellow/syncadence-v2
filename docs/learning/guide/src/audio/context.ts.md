ブラウザで音を鳴らすための土台 `AudioContext` と、ピアノの音源 `Sampler` を、アプリ全体で 1 組だけ作って使い回すためのファイルです。

## このファイルが担うもの

- `AudioContext`（Web Audio の音の土台）を、最初に必要になったときに 1 つだけ作る（L13）。
- その `AudioContext` で鳴らすピアノの音源 `Sampler`（`src/audio/sampler.ts`）も同時に 1 つ作る（L14）。
- 2 回目以降の呼び出しでは、作ってあるものをそのまま返す（L12・L16）。

**Web Audio** は、ブラウザに組み込まれた音の部品です。`AudioContext` はその中心で、音を作る部品をつなぐ「配線盤」と、音の時刻を数える「時計」（`currentTime`）を持っています。このゲームでは、音を鳴らす時刻も、判定の基準の時刻も、すべてこの 1 つの時計で決めます（`docs/design.md` の 5 節）。

## 呼ぶ・呼ばれる

| 向き | 相手 | 何のために |
|---|---|---|
| 呼ばれる | `src/ui/Play.tsx`（L51） | プレイ画面を開いて曲を読み込んだ後、`ctx` と `sampler` を受け取り、音源を読み込んで `PlayEngine` に渡す |
| 呼ばれる | `src/ui/Calibrate.tsx`（L42） | タイミング調整の画面で、クリック音を鳴らすための `ctx` を受け取る |
| 呼ぶ | `src/audio/sampler.ts` の `Sampler` | ピアノの音源を作る |
| 呼ぶ | ブラウザの `AudioContext` | 音の土台を作る |

## このファイルで初めて出てくる文法

- L8 `let kit: AudioKit | null = null` — ファイルの中で値を覚えておく変数（`let` は `src/game/session.ts` の L88-111 の解説）
- L12 `if (!kit)` — 値が「無い」かを `!` で調べる

## 読みどころ

- **1 つだけ作る理由。** ブラウザは同時に作れる `AudioContext` の数に上限を設けていることがあり、作るたびに音の装置を確保するので重くもなります。さらに、音の時刻とノーツの時刻を同じ時計で揃えたいので、時計は 1 つにしておく必要があります。
- **`latencyHint: "interactive"`**（L13）。「遅れを小さくしてほしい」というブラウザへの頼みです。

## 落とし穴

- **ブラウザは、ページで何か操作されるまで音を鳴らさせません**（自動再生の制限）。操作の前に作った `AudioContext` は `"suspended"`（一時停止）の状態で始まり、操作の中で `resume()` を呼ぶまで時計が進みません（`docs/research/03-web-audio-timing.md` の 6 節）。L10 のコメントの「ユーザー操作の中で最初に呼ぶ」はこのためです。
- ただし `src/ui/Play.tsx` の L51 は、曲のデータを読み終えた後（クリックやキー操作の処理の外）で `audioKit()` を呼んでいます。それでも鳴るのは、プレイを始める操作の中で `src/game/engine.ts` の `start` が `ctx.resume()`（L84）を呼び直しているからです。
- `AudioContext` を閉じる処理はどこにもありません。ページを開いている間、ずっと 1 つを使い続けます。

`AudioKit` は、`audioKit()` が返す 2 つ組の形です（`interface` と `readonly` は文法の索引の『interface と readonly』）。

| 欄 | 中身 |
|---|---|
| `ctx` | 音の土台 `AudioContext`。音の部品をつなぐ先であり、`currentTime`（秒）で時刻を数える時計でもある |
| `sampler` | その `ctx` で鳴らすピアノの音源 |

2 つを組にしているのは、音源の音の部品は作った `AudioContext` の中でしか使えず、別々に作ると取り違える恐れがあるからです。

@@ 8-9

`kit` は、作った 2 つ組を覚えておく変数です。型 `AudioKit | null` は「2 つ組か、まだ作っていないことを表す `null`」で、最初は `null` にしておきます。

この変数は関数の外、ファイルの一番外側に置いた `let` です。こう置いた変数は、ファイルが最初に読み込まれたときに 1 回だけ作られ、ページを開いている間ずっと値を保ちます。`export` していないので、このファイルの外からは直接読み書きできず、`audioKit()` を通してしか手に入りません。

@@ 10-17

> **文法: `!` で値が「無い」かを調べる**
>
> `!x` は「`x` が偽とみなされる値なら真」になります。偽とみなされるのは `false`・`0`・空の文字列 `""`・`null`・`undefined` などです。オブジェクトは中身に関係なく真とみなされます。
>
> L12 の `if (!kit)` は、`kit` が `null`（まだ作っていない）なら中に入る、という意味になります。

`audioKit()` は次のように動きます。

1. L12 まだ作っていなければ、
2. L13 `new AudioContext({ latencyHint: "interactive" })` で音の土台を作り、
3. L14 それを使う `Sampler` も作って、2 つ組を `kit` に入れる。`{ ctx, sampler: … }` の `ctx` は `ctx: ctx` の省略形です。
4. L16 `kit` を返す。2 回目以降は 1〜3 を飛ばして、同じ 2 つ組を返します。

このように「初めて頼まれたときに 1 つだけ作り、あとは同じものを返す」作り方を、**シングルトン**と呼びます。

`latencyHint` は、音の遅れと安定さのどちらを優先するかをブラウザに伝える設定です。`"interactive"` は「操作に反応して鳴らすので、遅れをできるだけ小さく」という意味で、ブラウザはそれに合わせて、音を作ってから出すまでの溜め（バッファ）を小さくします。溜めが小さいほど遅れは減りますが、処理が間に合わないと音が途切れやすくなります。実際の遅れの大きさは `ctx.baseLatency` と `ctx.outputLatency` で読めて、`src/audio/clock.ts` の L34 が使います。
