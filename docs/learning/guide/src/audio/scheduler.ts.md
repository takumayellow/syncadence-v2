曲の伴奏の音を、いまの位置から 0.4 秒先までずつ、`AudioContext` に「この時刻に鳴らして」と前もって予約していくファイルです。

## このファイルが担うもの

- 曲の音の一覧（`events`、時刻順）を先頭から順に見ていき、**先読みの範囲**（いまの曲の位置 + 0.4 秒）に入った音を予約する（`pump`、L17-30）。
- どこまで予約したかを `cursor`（L7）で覚え、同じ音を二度予約しない。
- 叩いて鳴らす音（キー音）を予約から外す（`skip`、L11・L23）。
- 0.05 秒より古くなった音は、鳴らさずに飛ばす（L23）。

実際に音を鳴らす処理は持たず、受け取った関数 `play` を呼ぶだけです。何を鳴らすか（ピアノの音源のどの音を、どの時刻に）は `src/game/engine.ts` が渡す関数が決めます。

**なぜ前もって予約するのか。** JavaScript で「0.5 秒後にこの音を鳴らす」とタイマーで書くと、画面の描画などで処理が詰まったときに数 ms〜数十 ms ずれます。一方、Web Audio の `start(時刻)` で予約した音は、ブラウザの音の仕組みが時刻どおりに鳴らします（`docs/research/03-web-audio-timing.md` の 2 節）。ただし曲 1 つ分（数百〜数千の音）を最初に全部予約すると、音の部品が一度に大量にでき、テンポを変えたり一時停止したりもしにくくなります。そこで、毎フレーム「少し先まで」を予約していきます。

| 使う型 | `src/song/types.ts` の `MusicEvent` | 音 1 つの 5 つ組 `[開始秒, 音高, 長さ, 強さ, 手]` |

## 読みどころ

- **`pump` の `while`**（L20-28）。時刻順に並んだ音を、先読みの範囲を超える最初の音で止まるまで進めます。止まった位置を `cursor` に残すので、次のフレームはその続きから見ます。
- **L23 の 2 つの条件。** 予約しない音が 2 種類あります（キー音と、古すぎる音）。どちらの場合もカーソルは進めます（L27）。

## 落とし穴

- **`events` が時刻順に並んでいることを前提にしています。** L22 で最初に範囲を超えた音で止まるので、もし後ろに早い音があっても見つけられません。並べているのは `tools/chart.py` の `event_order`（L81-83）で、`tools/build_songs.py` がその順で JSON に書き出します。
- **`songTime` は「聞こえている位置」ではなく、`AudioContext` が処理している位置です。** `engine.ts` の L183 は `(ctx.currentTime − startContextTime) × rate` を渡しています。出力の遅れを引いた位置から先読みすると、予約がその分だけ遅れるからです（L182 のコメント）。
- **先読みの 0.4 は曲の秒です。** 再生速度 0.5 では、実際には 0.8 秒先まで予約することになります。
- `pump` の戻り値（予約した数）と `finished`（L32-34）は、このコミットでは試験からしか使われていません。

> **文法: 関数の型**
>
> `(event: MusicEvent, index: number) => void` は、「`MusicEvent` と数の 2 つを受け取り、何も返さない関数」という**型**です。アロー関数（文法の索引の『アロー関数』）と同じ形をしていますが、`=>` の右に書くのは処理ではなく戻り値の型です。

> 関数も数や文字列と同じく値なので、引数として渡したり、欄にしまったりできます。その値に付ける型がこれです。

`PlayEvent` は、予約するときに呼ぶ関数の型です。受け取るのは音 1 つと、その音の `events` での番号です。`engine.ts` の L64 で渡している関数は番号を使わないので、`(event) => …` と 1 つ目だけを受け取っています。少なく受け取るのは構いません。

@@ 5-15

`EventScheduler` は予約係のクラスです（`class` は文法の索引の『class と constructor』）。

`cursor`（L7）は、`events` のうち次に見る音の番号です。0 から始まり、増える一方で戻りません。

コンストラクタは 4 つの引数を受け取り、そのまま欄にします（文法の索引の『private とコンストラクタ引数のプロパティ』）。

| 引数 | 中身 |
|---|---|
| `events` | 曲の音の一覧。時刻順 |
| `skip` | 予約しない音の番号の集まり（キー音） |
| `play` | 予約するときに呼ぶ関数 |
| `lookahead` | 先読みの幅（曲の秒）。省けば 0.4 |

`skip` の型 `ReadonlySet<number>` は、番号の「集まり」（文法の索引の『Map と Set』）を、中身を足したり消したりせずに読むだけで使う、という型です。`has(番号)` でその番号が入っているかを調べられます。

`skip` に入るのは、キー音モードのときに、譜面のノーツが鳴らす音（`links`）の番号です。`engine.ts` の L60-63 が、全ノーツの `links` を集めて作ります。キー音モードでは、これらの音はノーツを叩いたときに鳴らす（`engine.ts` の L129-134）ので、予約で鳴らすと二重になります。キー音モードでなければ空の集まりで、全部の音を予約します。

@@ 16-31

`pump(songTime)` は、曲の位置 `songTime` から `lookahead` 秒先までの音を予約し、予約した数を返します。

1. L18 先読みの終わり `horizon` を、`songTime + lookahead` に決める。
2. L20 カーソルが最後に届くまで繰り返す。
3. L21-22 カーソルの位置の音の開始時刻（`event[0]`）が `horizon` より後なら、そこで止める。続きは次の `pump` で見る。
4. L23-26 キー音でなく（`!this.skip.has(…)`）、しかも開始時刻が `songTime − 0.05` 以降なら、`play` を呼んで予約し、数える。
5. L27 予約したかどうかにかかわらず、カーソルを 1 つ進める。

試験（`src/audio/audio.test.ts` の L77-90）の例で追うと分かりやすくなります。音の開始時刻が 0・0.2・0.5・0.9・1.5 秒の 5 つ、先読み 0.4 秒のとき、

| 呼び出し | 先読みの範囲 | 予約される音 | 理由 |
|---|---|---|---|
| `pump(0)` | 〜0.4 秒 | 0 秒・0.2 秒 | 0.5 秒の音で止まる |
| `pump(0.1)` | 〜0.5 秒 | 0.5 秒 | 0 と 0.2 はもう予約済み（カーソルが先にある） |
| `pump(1.4)` | 〜1.8 秒 | 1.5 秒 | 0.9 秒の音は 1.4 − 0.05 = 1.35 秒より古いので飛ばす |

3 つ目は、フレームが長く止まったとき（タブを裏に回して描画が止まった後など）に起きることです。もう過ぎた音を全部予約すると、戻った瞬間にまとめて鳴ってしまうので、0.05 秒より古い音は鳴らしません（`docs/design.md` の 5.1 節）。

予約の時刻は、`engine.ts` の L65 が `clock.contextTimeOf(event[0])`（`src/audio/clock.ts` の L65-67）で曲の位置から `AudioContext` の時刻に直します。少し過ぎた時刻（0.05 秒以内）を指定された音は、Web Audio がすぐに鳴らします。

毎フレーム（60 フレーム毎秒なら約 17 ms ごと）呼ばれるので、0.4 秒の先読みは何十フレーム分もの余裕になります。数フレーム処理が詰まっても、その間に鳴らす音は予約済みなので途切れません。
