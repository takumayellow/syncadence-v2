MIDI ファイルを読み、「どの音が、何秒に、どちらの手で、拍のどれくらい強い位置で鳴るか」を引ける楽譜データ（`Score`）に変える、譜面づくりの土台のファイルです。

## このファイルが担うもの

- MIDI の中の時刻は「tick」という整数の目盛りで書かれています。それを秒に直すテンポマップ（`TempoMap`、L46-76）。
- 拍子・小節線・拍の位置を求め、各音が小節頭・拍頭・半拍…のどこにあるか（拍節の強さ、`metric_level`、L110-120）を返す。
- LilyPond が出す MIDI は、曲が小節の途中から始まる「弱起（アウフタクト）」を tick 0 から詰めて書きます。そこで `.ly` の `\partial` から弱起の長さを読み（`read_pickup`、L153-165）、小節の起点をその分ずらす。
- トラックごとの平均の音の高さで、右手と左手を分ける（L202-204）。
- ダンパーペダル（MIDI のコントロールチェンジ 64 番）の区間を読み、音が実際に鳴り続ける長さを求める（`sounding_end`、L145-150）。

ここでは譜面を作りません。譜面は `tools/chart.py` が、このファイルの `Score` を材料に作ります。

## 読みどころ

- `TempoMap`（L46-76）。tick を秒に直す計算と、テンポが途中で変わる曲での区分ごとの足し合わせ。
- `metric_level`（L110-120）。譜面の難易度を決める一番の材料で、`tools/chart.py` は「EASY は強い位置の音だけ」のように、この値で音を選びます。
- `read_pickup`（L153-165）と `_origin`（L104-108）。弱起の扱いで、拍節の強さがずれないようにしている所です。
- `load_score`（L168-230）。MIDI の「鍵盤を押した・離した」という出来事の列を、1 音ずつの `Note` に組み立て直す所です。

## 落とし穴

- **弱起は最初の拍子の区間にしか効かない**（L106-108）。途中で拍子が変わる曲（収録曲では `arabesque-1`）でも、後の区間は拍子が変わった tick を小節頭とみなします。
- **L128-129 と L131 の条件は、収録曲では結果を変えない。** 理由は L122-144 の解説に書きます。
- **閉じられなかった音は黙って捨てられる**（L189-195）。「押した」に対応する「離した」が無い音は `Note` になりません。
- **同じ tick にテンポが 2 つあるときは、値の大きい方（遅い方）が残る**（L51 と L62-64）。ファイルの中での順番ではありません。
- **右手・左手はトラック単位で決める**（L202-204）。1 つのトラックの中で手が入れ替わる楽譜は、そのまま片方の手として扱われます。

> **文法: 取り出さないグループ `(?:…)`**
>
> 正規表現の `( )` は、まとめる働きと、一致した部分を後で `group(番号)` で取り出す働きを兼ねます。`(?: )` は**まとめるだけ**で、番号を付けません。後ろに `?`（0 回か 1 回）を付けて「この塊ごと、あってもなくてもよい」とするときによく使います。

**ペダルの定数（L21-22）** — MIDI のコントロールチェンジ（つまみやペダルの値を送る出来事）の 64 番がダンパーペダルで、値は 0〜127 です。64 以上を「踏んでいる」とみなします（L188）。

**`PARTIAL`（L23）** — LilyPond の楽譜で弱起の長さを書く `\partial 8` のような命令を探します。生文字列（文法の索引の『正規表現と生文字列 `r"…"`』）の中なので、`\\partial` は「`\` という文字そのもの」+ `partial` です。

| 部分 | 意味 | 取り出し |
|---|---|---|
| `\\partial` | `\partial` という文字 | |
| `\s+` | 空白 1 個以上 | |
| `(\d+)` | 数字 1 個以上。音符の種類（4 なら 4 分音符、8 なら 8 分音符） | `group(1)` |
| `(\.*)` | `.` が 0 個以上。付点の数 | `group(2)` |
| `(?:\s*\*\s*(\d+)(?:/(\d+))?)?` | 省略できる「`*` 数」または「`*` 数`/`数」。長さの倍率 | `group(3)`・`group(4)` |

一致する例と、取り出される値:

| 書き方 | group(1) | group(2) | group(3) | group(4) |
|---|---|---|---|---|
| `\partial 8` | `"8"` | `""` | `None` | `None` |
| `\partial 4.` | `"4"` | `"."` | `None` | `None` |
| `\partial 4*3` | `"4"` | `""` | `"3"` | `None` |
| `\partial 8*3/2` | `"8"` | `""` | `"3"` | `"2"` |

省略できる部分が一致しなかったときは、そのグループは `None` になります。この値を `read_pickup`（L153-165）が tick に直します。

> **文法: @dataclass**
>
> `@` で始まる行は**デコレータ**で、すぐ下のクラスや関数を受け取って、手を加えたものに置き換える書き方です。`@dataclass` は「下のクラスを、データを入れておく箱として仕上げる」デコレータです。
>
> ```python
> @dataclass(frozen=True)
> class Note:
>     start: int
>     end: int
> ```
>
> のように、クラスの中に `名前: 型` を並べるだけで、Python が次のものを自動で作ります。
>
> - **作るための関数** — `Note(0, 96, 76, 62, "R")` と、並べた順に値を渡すと箱ができる。`Note(start=0, end=96, …)` と名前で渡すこともできる。
> - **中身の取り出し** — `n.start`、`n.pitch` のように `.名前` で読める。
> - **比べる仕組み** — 2 つの箱は、中身がすべて等しければ `==` で等しい。
> - **表示** — `print(n)` で `Note(start=0, end=96, pitch=76, velocity=62, hand='R')` と出る。
>
> `frozen=True` を付けると、作った後に中身を書き換えられなくなります（`n.start = 5` はエラー）。値が変わらないことが保証されるので、安心してあちこちに渡せます。代わりに、変えたいときは新しい箱を作ります。
>
> ここでの型注釈（`start: int`）は、dataclass にとっては「どんな項目があるか」の宣言そのものです。ただし型の検査はしないので、`int` の所に小数を入れても動いてしまいます。

> **文法: コメント `#`**
>
> `#` から行末までは説明書きで、Python は読み飛ばします。L28 の `# tick` は「この数は tick 単位」という注記です。

**`Note`（L26-32）** は 1 つの音です。

| 項目 | 中身 | 例（`fur-elise` の最初の音） |
|---|---|---|
| `start` | 鍵盤を押す tick | `0` |
| `end` | 鍵盤を離す tick | `96` |
| `pitch` | 音の高さ（MIDI のノート番号。60 が真ん中のド、1 増えるごとに半音上） | `76`（ミ） |
| `velocity` | 強さ（1〜127） | `62` |
| `hand` | `"R"`（右手）か `"L"`（左手） | `"R"` |

**tick について。** MIDI では時刻を「4 分音符 1 つを何等分するか」で決めた整数の目盛りで書きます。この等分の数が `ticks_per_beat`（このファイルでは `tpb`）で、収録 12 曲はすべて 384 です。つまり 4 分音符 = 384 tick、8 分音符 = 192 tick、16 分音符 = 96 tick です。tick を秒に直すにはテンポが要ります（L46-76）。

**`TimeSignature`（L35-39）** は「`tick` から先は `numerator`/`denominator` 拍子」という 1 件の拍子です。`fur-elise` は `TimeSignature(tick=0, numerator=3, denominator=8)`、つまり最初から 8 分の 3 拍子です。

> **文法: `in` による所属の判定**
>
> `x in (6, 9, 12)` は「`x` がこの並びのどれかと等しければ `True`」です。リスト・タプル・文字列・辞書（キーを見る）・集合に使えます。L43 では `==` と `and` で「分母が 8、かつ分子が 6・9・12 のどれか」をつないでいます。

**複合拍子**かどうかを判定します。8 分の 6・9・12 拍子は、8 分音符 3 つ（付点 4 分音符 1 つ）を 1 拍として数えます。6/8 なら 2 拍、9/8 なら 3 拍、12/8 なら 4 拍です。収録曲では `clair-de-lune` が 9/8 です。

8 分の 3 拍子（`fur-elise`）は複合拍子に**入れていません**。8 分の 3 を付点 4 分 1 拍とすると 1 小節 1 拍になってしまうので、8 分音符を 1 拍としています（L96-99 の結果、1 拍 = 192 tick）。

**MIDI のテンポ。** MIDI の `set_tempo` は「4 分音符 1 つが何マイクロ秒（100 万分の 1 秒）か」を表します。`500_000` は 0.5 秒 = 1 分に 120 拍で、MIDI の決まりではテンポの指定が無いときはこの値です。よって 1 tick の秒数は

```
テンポ（マイクロ秒/4 分音符） ÷ 1,000,000 ÷ tpb
```

です。`fur-elise` はテンポ 833333 なので、1 tick = 833333 / 1e6 / 384 ≈ 0.00217 秒、4 分音符 = 0.833 秒（1 分に 72 拍）です。

**`__init__` が作るもの。** テンポが途中で変わる曲のために、変わり目ごとに 3 つのリストを並べて持ちます。

| リスト | i 番目の中身 |
|---|---|
| `_ticks` | i 番目のテンポが始まる tick |
| `_tempos` | そのテンポ |
| `_seconds` | その tick が曲の頭から何秒か |

手順:

1. L51: 変わり目の組 `(tick, テンポ)` を tick の順に並べる（タプルは 1 つ目の値で比べ、同じなら 2 つ目で比べる）。1 つも無ければ 120 BPM の 1 件にする。
2. L52-53: 最初の変わり目が tick 0 でなければ、頭に `(0, 500000)` を足す。`points[0][0]` は「先頭の組の、1 つ目の値（tick）」。
3. L58-61: 2 件目からは、ひとつ前の変わり目からここまでの tick 数 × 前のテンポの 1 tick の秒数を `elapsed` に足していく。これで各変わり目の「頭からの秒数」が出る。
4. L62-64: 直前に入れた変わり目と同じ tick なら、テンポだけ上書きして次へ。
5. L65-67: 3 つのリストに足す。

例（`tools/tests/test_score.py` と同じ値）: tpb 480、変わり目 `[(0, 500000), (960, 1000000)]` なら、

- 1 件目は `elapsed = 0.0`。
- 2 件目は `(960 - 0) × 500000 / 1e6 / 480 = 1.0` 秒。

で、`_seconds` は `[0.0, 1.0]` になります。

同じ tick にテンポが 2 つあると（手順 4）、L51 で `(tick, テンポ)` の順に並べ替えた後なので、**値の大きい方**が後に来て残ります。収録曲では `traumerei` に tick 0 の同じ値（1000000）が 2 つあり、39 件の `set_tempo` が 38 件の変わり目になります。同じ値どうしなので結果は変わりません。

テンポの変わり目の数は、`fur-elise` など 9 曲が 1 件（ずっと同じテンポ）、`mountain-king` が 2 件（tick 75264 = 85.22 秒から 1 分 138 拍 → 154 拍）、`fantaisie-impromptu` が 5 件、`traumerei` が 38 件（細かく遅くなったり戻ったりする）です。

> **文法: 二分探索 `bisect.bisect_right`**
>
> `bisect.bisect_right(並んだリスト, x)` は、昇順に並んだリストに `x` を入れるとしたら何番目に入るか（同じ値があればその**右**）を返します。リストを半分ずつ絞って探すので、長いリストでも速く見つかります。
>
> `[0, 960]` に対して: `bisect_right(…, 500)` は 1、`bisect_right(…, 960)` は 2、`bisect_right(…, 0)` は 1。

**`seconds`** — tick を秒に直します。

1. L70: `bisect_right(...) - 1` で「`tick` 以下で最後の変わり目」の番号 `i` を出す。
2. L71: `tick` が負のときは `-1` になるので、0 に寄せる（`max(i, 0)`）。
3. L72: その変わり目の秒数 + そこからの tick 数 × そのテンポの 1 tick の秒数。

さっきの例で `seconds(1440)` は、`i = 2 - 1 = 1`、`1.0 + (1440 - 960) × 1000000 / 1e6 / 480 = 1.0 + 1.0 = 2.0` 秒です。テンポが倍の長さ（半分の速さ）になったので、同じ 480 tick でも前半の 2 倍の 1 秒かかっています。

引数の型が `float` なのは、`tools/chart.py` などから小数の tick が渡ることもあるためです（`int` も受け取れます）。

1. L216-221: ペダルの出来事を tick の順に見て、「踏んだ → 上げた」の組を区間にする。踏んだまま 2 回目の「踏んだ」が来ても無視し（`down_at is None` のときだけ記録）、踏んでいないときの「上げた」も無視する。`down_at: int | None = None` は「整数か、まだ無いか」の変数です。
2. L222-223: 最後まで上げなかったら、曲の終わりまで踏んでいたことにする。
3. L225-227: `.ly` が渡されて実在すれば、`read_pickup` で弱起を読む。
4. L229-230: 一番遅く離す音の tick を出し、トラックの終わりと比べた大きい方を曲の終わりにして、`Score` を作って返す。
