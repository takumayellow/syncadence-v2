保存してある楽譜から、ゲームが読み込む曲データ（`public/songs/<曲ID>.json`）と曲の一覧（`public/songs/index.json`）を書き出すファイルです。

## このファイルが担うもの

`tools/` の 3 つの道具をつなぐ、最後の工程です。

1. `tools/fetch_sources.py` が保存した楽譜（MIDI と LilyPond）と出どころの記録（`meta.json`）を読む。
2. `tools/score.py` の `load_score` で、楽譜を秒で扱える `Score` にする。
3. `tools/chart.py` で 4 つの難易度の譜面を作る。
4. 鳴らす音（`events`）・譜面（`charts`）・小節線・拍・出典などを 1 つの辞書にまとめ、JSON で書き出す。
5. 全曲の要約を集めて、曲選びの画面が読む一覧を書き出す。

docstring（L5-6）のとおり、鳴らす音と譜面は**同じ楽譜から同じ時間軸で**作るので、ノーツを叩くタイミングと鳴る音が作りの上でずれません。

## 落とし穴

- **`bpm` は 4 分音符の速さ。** 1 拍が 8 分音符の曲（`fur-elise` は 3/8 拍子）でも、4 分音符で数えます。`fur-elise` の `bpm` は 72 ですが、1 拍（8 分音符 0.417 秒）で数えれば 144 です。曲の途中でテンポが変わっても、一覧に出るのは曲の頭の速さだけです（L41）。
- **曲 ID を指定しても、全曲の `meta.json` と曲データを読む。** L79 はすべての曲で `meta.json` を読み、L85 はすべての曲で書き出し済みの JSON を読みます。一度も作っていない曲があると、そこでファイルが見つからずに止まります。
- **曲データは改行も空白も無い 1 行。** L84 で区切りの空白を省いているので、`fur-elise.json` は 1 行で約 56 KB です（空白ありなら約 67 KB）。人が読むには整形して開く必要があります。一覧の `index.json` の方は、1 文字ずつ字下げして読みやすく書きます（L93）。

> **文法: 辞書の合体 `|`**
>
> `辞書A | 辞書B` は、A のキーと値に B のキーと値を足した、**新しい**辞書を作ります（A も B も変わりません）。同じキーがあれば B の値が勝ちます。L88-91 では、8 つのキーを抜き出した辞書に、`levels` と `noteCounts` の 2 つのキーを足しています。Python 3.9 からの書き方です。

> **文法: f 文字列の書式指定**
>
> f 文字列（文法の索引の『f 文字列』）の `{ }` の中で、値の後に `:` と書式を書くと、表示の形を指定できます。
>
> - `{entry['id']:22s}` — 文字列（`s`）を 22 文字の幅で左寄せにし、足りない分を空白で埋める。曲 ID の長さが違っても、次の列がそろう。
> - `{payload['duration']:6.1f}` — 小数（`f`）を小数第 1 位までに丸め、全体を 6 文字の幅で右寄せにする。130.417 は `" 130.4"`。

> **文法: 文字列をつなぐ `join`**
>
> `"  ".join(並び)` は、並びの文字列を、間に `"  "`（空白 2 つ）をはさんでつないだ 1 つの文字列にします。区切りの文字列の方に `.join` を付けるのが Python の書き方です。

> **文法: コマンドに付けた引数 `sys.argv`**
>
> `sys.argv` は、Python を動かしたときのコマンドの単語のリストです。`python tools/build_songs.py fur-elise clair-de-lune` なら `["tools/build_songs.py", "fur-elise", "clair-de-lune"]` で、先頭は動かしたファイルの名前です。`sys.argv[1:]` はスライス（文法の索引の『集合とスライス』）で、先頭を除いた曲 ID だけのリストになります。

直接動かしたときだけ `main` を呼び、その戻り値を終了コードにします（文法の索引の『`if __name__ == "__main__":`』）。`main` に引数のリストを渡す形にしてあるので、テストなどから `main(["fur-elise"])` と呼ぶこともできます。
