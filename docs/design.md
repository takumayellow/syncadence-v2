# Syncadence v2 の設計

調査の記録は [research/](research/README.md) にある。この文書は、そこから決めた v2 の作りをまとめる。

## 1. 方針: 楽譜から音もノーツも作る

v1 は Public Domain の録音を素材にし、録音から検出したオンセットにノーツを置いた。時刻の精度は中央値 6〜12 ms で足りていたが、譜面に拍子・格子が無いこと、旋律を追わないこと、レーンが音高と結び付かないことから、「曲に合っていない」と感じる譜面になった（[00-v1-diagnosis.md](research/00-v1-diagnosis.md)）。

v2 は素材を楽譜に変える。Mutopia Project の Public Domain の楽譜（LilyPond の .ly と、それから書き出した MIDI）を 1 曲につき 1 つ使い、同じ音の列から次の 2 つを作る。

- 鳴らす音: ブラウザで、CC0 のピアノのサンプル（FreePats Upright Piano KW）を使って MIDI の音を 1 つずつ鳴らす。
- ノーツ: 小節・拍・声部の情報を使って、旋律の音に置く。

この形にすると、次のことが構成上成り立つ。

| 性質 | 理由 |
|---|---|
| ノーツと音がずれない | ノーツは鳴らす音そのものを指している（ノーツ → 音の添字） |
| 拍子どおりに間引ける | 音ごとに、小節頭・拍頭・半拍…のどの格子の上にあるかが分かる |
| 旋律を追える | 右手・左手の譜表と、同時に鳴る音の上下関係が分かる |
| テンポを変えても音高が変わらない | 録音の伸縮ではなく、発音時刻を伸ばすだけで済む |
| 叩いた音だけ鳴らすモード（キー音）が作れる | ノーツごとに鳴らす音が決まっている |
| 権利の確認が楽譜の版だけで済む | 演奏の録音を使わないので、録音の権利を考えなくてよい |

失うものもある。演奏の表情（ルバート、ペダルの響き）は MIDI の範囲に限られ、録音ほど豊かにはならない。曲は Mutopia にある Public Domain の版に限られる。

## 2. 全体の構成

```
tools/（Python, ビルド時）                       src/（TypeScript + React, 実行時）
  fetch_sources.py  Mutopia から .ly と MIDI      song/     曲データの型・検証・読み込み
                    を取得し、PD を検査            audio/    サンプラー、時計、発音の予約
  build_samples.py  ピアノ音源を mp3 にして目録    game/     判定、プレイの進行、較正
  score.py          MIDI → 小節・拍・声部付きの音   render/   レーンの描画（Canvas 2D）
  chart.py          音の列 → 難易度別の譜面         ui/       画面（選曲・プレイ・結果・較正）
  build_songs.py    public/songs/*.json を書き出す
```

曲データは事前に作って `public/songs/` に置く。ブラウザは JSON を読むだけで、譜面を実行時には作らない。

| 置き場所 | 中身 |
|---|---|
| `tools/songs.json` | 曲の目録（Mutopia の ID、.ly と MIDI のパス、日本語の題名） |
| `sources/mutopia/<id>/` | 取得した .ly・MIDI と、出どころ・SHA-256・ライセンスを書いた `meta.json` |
| `public/songs/index.json` | 選曲画面用の一覧（難易度ごとのレベルとノーツ数） |
| `public/songs/<id>.json` | 1 曲分のデータ（下の 3 節） |
| `public/samples/kw/` | ピアノの mp3 66 個、目録 `manifest.json`、音源の LICENSE と README |

## 3. 曲データの形式

`public/songs/<id>.json`（`version: 2`）は次を持つ。時刻はすべて曲頭からの秒。

| フィールド | 内容 |
|---|---|
| `events` | 鳴らす音の列。`[時刻, 音高, 長さ, ベロシティ, 手(0=右,1=左)]` |
| `bars`, `beats` | 小節線と拍の時刻（描画用） |
| `charts.<難易度>` | `lanes`（4 か 6）、`level`、`notes` |
| `notes` の各要素 | `[時刻, レーン, 長さ(0ならタップ), 鳴らす音の添字の列]` |
| `credit` | Mutopia の ID・曲のページ・浄書者・ライセンス |

ノーツは鳴らす音を添字で指す。ブラウザ側の `src/song/validate.ts` は、レーンが範囲内であること、添字が `events` の範囲内であること、曲 ID の形式（`^[a-z0-9-]{1,64}$`）を読み込み時に検査する。

## 4. 譜面の作り方（`tools/chart.py`）

### 4.1 拍節レベル

`score.py` は MIDI の拍子記号とテンポの変化を読み、音ごとに拍節レベルを付ける。

| レベル | 位置 |
|---|---|
| 0 | 小節の頭 |
| 1 | 拍の頭 |
| 2 | 半拍（6/8 などの複合拍子では 1/3 拍） |
| 3 | さらにその半分 |
| 4 | それ以外（3 連符・装飾音など） |

弱起の曲は、MIDI だけでは小節の始まりが分からない。.ly の `\partial` から弱起の長さを読み、小節線をその分ずらす。

### 4.2 旋律を取り出す

1. 右手の各発音時刻で最も高い音を旋律の候補にする。ただし、それより高い音がまだ鳴り続けているなら内声とみなして外す。
2. 右手が休んでいる小節は、左手の最も低い音の列で代わりにする。
3. 70 ms より短く、拍の格子から外れた（レベル 4 の）右手の音は装飾音とみなし、旋律に入れない。

### 4.3 難易度ごとに採る

小節ごとに、難易度の上限に収まる範囲で最も細かい拍節レベルまで旋律の音を採る。拍の頭から順に採るので、間引いても拍の格子からはみ出さない。

| 難易度 | レーン | 採る最大レベル | 密度の上限（notes/s） | 最小間隔（s） | ロングにする長さ | 左手を足すレベル |
|---|---|---|---|---|---|---|
| EASY | 4 | 1（拍頭まで） | 1.8 | 0.36 | 0.9 s かつ 2 拍 | 足さない |
| NORMAL | 4 | 2（半拍まで） | 3.0 | 0.21 | 0.7 s かつ 1.5 拍 | 足さない |
| HARD | 6 | 3 | 4.8 | 0.14 | 0.6 s かつ 1 拍 | 0（小節頭） |
| EXPERT | 6 | 4（全部） | 7.5 | 0.095 | 0.5 s かつ 1 拍 | 1（拍頭） |

その後に次の処理をする。

- 最小間隔より詰まったノーツは、拍節レベルの低い（強い拍の）方を残す。
- 難易度ごとの長さ（EASY は 2 拍）より長い空白は、採らなかった旋律の音で埋める。遅い曲で EASY がすかすかにならないようにするためである。
- 上の表の長さ以上続く音はロングノーツにする。
- HARD と EXPERT では、強拍の左手の音を、旋律との同時押しか単独のノーツとして足す。

### 4.4 レーン

レーンは旋律の上下の動きを左右に写す。

- 前後 3 秒の旋律の音域に対する相対的な高さで、基準のレーンを決める。音域が 7 半音より狭いときは 7 半音に広げ、狭い旋律でもレーンが詰まりすぎないようにする。
- 直前の音より高ければ右へ、低ければ左へ動かす。同じ音の繰り返しは同じレーンに置き、間隔が `jack_gap` より短いときだけ隣のレーンへずらす。
- 同じレーンを短い間隔（`jack_gap`）で続けて叩かせない。ロングノーツが終わるまで、そのレーンには次のノーツを置かない。間隔に余裕のあるレーンが無ければ前のノーツと重ならないだけのレーンに置き、それも無ければその音はノーツにしない。
- 左手の音は左端のレーン（6 レーンでは、C3 以上の音は左から 2 番目）に置く。

### 4.5 レベル

2 秒の窓で数えた密度の 90 パーセンタイルを p90 として、`レベル = round(1 + p90 × 3.2)` で目安を出す。

### 4.6 検査

`tools/tests/` の pytest が、同梱の 12 曲すべてについて次を確かめる。

- ノーツの時刻が、指している音の発音時刻と一致する。
- レーンが範囲内で、同じレーンのノーツが重ならない。
- 最小間隔を守っている。
- EASY のノーツの 90% 以上が拍頭か半拍（レベル 2 以下）にある。
- 難易度が上がるとノーツ数が減らない。
- EASY と NORMAL で、旋律の上下の向きが 75% 以上一致する。

## 5. 同期（`src/audio/`, `src/game/engine.ts`）

調査の内容は [03-web-audio-timing.md](research/03-web-audio-timing.md) にある。基準の時計は `AudioContext` 1 つにまとめる。

### 5.1 音の予約

曲の 0 秒を鳴らす `AudioContext` の時刻を開始時に 1 つ決め、各音をその時刻からの相対で予約する。毎フレーム、`ctx.currentTime` から 0.4 秒先までの音を予約する（`EventScheduler`）。0.05 秒より古くなった音は鳴らさずに飛ばす（タブを裏にした後など）。

テンポを変えたときは、予約時刻を `1 / 速さ` 倍に伸ばす。サンプルの再生速度は音高だけで決まるので、音高は変わらない。

### 5.2 「いま聞こえている位置」

描画と判定には、スピーカーから出ている音の位置を使う（`SongClock`）。

1. `ctx.getOutputTimestamp()` が返す「出力された AudioContext 時刻」と `performance.now()` の対応を取る。
2. その値が `currentTime` から 0.5 秒以上離れている（壊れている）ときは、`currentTime − baseLatency − outputLatency` で代わりにする。
3. 対応の揺れを指数移動平均（係数 0.05）でならす。25 ms を超える変化（中断・再開など）にはすぐ追従する。

### 5.3 入力の時刻

キーやタッチの判定には、ハンドラが動いた時刻ではなく `event.timeStamp` を使う。描画が詰まってハンドラの実行が遅れても、押した瞬間で判定できる。`timeStamp` が `performance.now()` と同じ基準でない環境に備えて、範囲外の値は現在時刻に置き換える（`eventTimeMs`）。

### 5.4 補正

ブラウザが申告しない遅れ（OS のミキサー、Bluetooth の一部）と押す癖は、利用者が補正する。

| 設定 | 効き方 |
|---|---|
| 入力の補正 | 判定に使う時刻から引く。正なら、遅めに押しても合う |
| 表示の補正 | 描画に使う時刻から引く。正なら、ノーツが遅れて届く |
| タイミングを測る | 600 ms 間隔のクリック 20 回に合わせて叩き、最初の 4 回を除いたずれの中央値を入力の補正にする |
| 結果画面の提案 | 20 回以上叩いて中央値が ±12 ms 以上ずれていれば、補正の変更を 1 ボタンで提案する |

## 6. 判定とスコア（`src/game/`）

判定幅は実時間の ±ms で決める。テンポを落としたときは、曲の時間差を速さで割って実時間に直してから判定する。

| 判定 | 幅 | スコアの重み |
|---|---|---|
| PERFECT | ±42 ms | 1 |
| GREAT | ±83 ms | 0.75 |
| GOOD | ±125 ms | 0.35 |
| MISS | 見逃し、または 125〜160 ms の早押し | 0 |

- 160 ms より早い押下は空振りとして無視する。
- ロングノーツは始点と終点で 2 つに数える。終点より 150 ms 以上早く離すと終点はミスになる。始点を逃したときは、終点も同時にミスにする。
- スコアは 重みの合計 ÷ 判定数 × 1,000,000。ランクは SSS（99 万）、SS（97 万）、S（94 万）、A（88 万）、B（80 万）、C（70 万）、D の順。

## 7. 画面と操作

| 画面 | 内容 |
|---|---|
| 選曲 | 難易度のタブ、曲の一覧（レベル・時間・ノーツ数・自己ベスト）、設定、遊び方、クレジット |
| プレイ | 開始前は曲名とクレジットを出し、何かキー（F キー・Tab・Esc・修飾キーとの組み合わせなど、ブラウザが使うキーを除く）か画面のタップで始める。Esc で一時停止し、R でやり直し、Q で選曲に戻る。タブを裏にすると一時停止する |
| 結果 | ランク、スコア、判定の内訳、最大コンボ、タイミングの中央値と早め・遅めの数 |
| 較正 | 5.4 節のタップ較正 |

キーは EASY・NORMAL が `D F J K`、HARD・EXPERT が `S D F J K L`。スマートフォンではレーンをタップする。

設定と自己ベストは `localStorage` に保存する。読み込むときは値の型と範囲を検査し、壊れた値は既定値に戻す。オートプレイの結果は自己ベストに残さない。

## 8. v1 との関係

v1（`takumayellow/syncadence-rhythm`）は録音を素材にする方式である。v2 は素材も譜面生成も作り直しているので、別のリポジトリに分けた。v1 から引き継いだのは、タップ較正と、開始前のキー入力で始める操作の 2 つである。

## 9. これからの課題

- ジムノペディの EASY と NORMAL が同じ譜面になる。半拍の音がほとんど無い曲では、2 つの差が付かない。
- 4 レーンでは左手の音を足さないので、左端のレーンの出番が少ない。
- レベルは密度だけから出しており、跳躍や同時押しの難しさを数えていない。
- 曲を増やすときは `tools/songs.json` に足し、`fetch_sources.py` → `build_songs.py` を実行する。PD の検査に通らない曲は取り込まれない。
